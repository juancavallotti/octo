This section is the complete reference for everything you can put in a flow file: every connector, source, and block type, plus the [CLI](/reference/cli), the [CEL expression language](/reference/cel), and the [flow file schema](/reference/flow-file).

The tables below catalogue every type by category. **Connectors** are configured under `connectors:` and referenced by name; **sources** bind a flow's entry point to a connector; **blocks** are the steps of a flow's `process` chain.

## Triggers and sources

| Type | Description | Reference |
|---|---|---|
| `http` | HTTP server connector; routes requests into flows and returns the flow result. | [HTTP](/reference/connectors/http) |
| `cron` | Trigger flows on a schedule. | [Cron](/reference/connectors/cron) |
| `events` | Broadcast pub/sub topics; every subscriber flow receives each event. | [Events](/reference/connectors/events) |
| `queue` | Competing-consumer queues; one worker flow receives each message. | [Queue](/reference/connectors/queue) |

## Control-flow blocks

Composites configured with top-level YAML keys, not `settings:`. All on one page: [Control Flow](/reference/blocks/control-flow).

| Type | Description |
|---|---|
| [`if`](/reference/blocks/control-flow#if) | Conditional branching on a CEL boolean expression. |
| [`switch`](/reference/blocks/control-flow#switch) | Multi-case routing; runs the first matching case or the default. |
| [`fork`](/reference/blocks/control-flow#fork) | Scatter the message across parallel branches, then join and pass through. |
| [`foreach`](/reference/blocks/control-flow#foreach) | Sequentially iterate an array, running the body per element. |
| [`enrich`](/reference/blocks/control-flow#enrich) | Run a body flow on an isolated copy, then merge back only the named body/variables. |
| [`validate`](/reference/blocks/control-flow#validate) | Assert CEL rules; reject and stop the flow when any fail. |
| [`handle-errors`](/reference/blocks/control-flow#handle-errors) | Run a process chain; on error, expose `vars.error` and run the error chain. |
| [`cache-scope`](/reference/blocks/control-flow#cache-scope) | Memoize the body flow's result in the runtime store, keyed by a CEL expression. |

## Data blocks

Reshape the message payload and variables: [Data](/reference/blocks/data).

| Type | Description |
|---|---|
| [`set-payload`](/reference/blocks/data#set-payload) | Replace the message body with the result of a CEL expression. |
| [`set-variable`](/reference/blocks/data#set-variable) | Store the result of a CEL expression in a named variable. |
| [`delete-variable`](/reference/blocks/data#delete-variable) | Remove a named variable from the message. |
| [`multi-transform`](/reference/blocks/data#multi-transform) | Apply an ordered list of additive CEL edits in one block. |

## Storage blocks

The runtime key-value store: [Storage](/reference/blocks/storage).

| Type | Description |
|---|---|
| [`object-read`](/reference/blocks/storage#object-read) | Read an object from the runtime store into the body or a variable. |
| [`object-write`](/reference/blocks/storage#object-write) | Write an object to the runtime store under a key. |
| [`object-delete`](/reference/blocks/storage#object-delete) | Delete an object from the runtime store by key. |
| [`invalidate-cache`](/reference/blocks/storage#invalidate-cache) | Evict a cache-scope entry by its key so the next run recomputes. |

## Integration blocks

Cross-flow and cross-system glue: [Integration](/reference/blocks/integration).

| Type | Description |
|---|---|
| [`flow-ref`](/reference/blocks/integration#flow-ref) | Invoke another flow by name, synchronously or fire-and-forget. |
| [`cli-run`](/reference/blocks/integration#cli-run) | Run a local program from an allow list; the events path watches its output line by line as it runs. |
| [`jwt-validate`](/reference/blocks/integration#jwt-validate) | Verify a bearer JWT against an OIDC provider; reject with 401 on failure. |
| [`template-resource`](/reference/blocks/integration#template-resource) | Render a declared template resource against the current message. |

## AI blocks

LLM-driven blocks and the MCP server: [AI Blocks](/reference/blocks/ai).

| Type | Description |
|---|---|
| [`ai-agent`](/reference/blocks/ai#ai-agent) | Let an LLM call flow branches as tools in a loop to accomplish a task. |
| [`ai-router`](/reference/blocks/ai#ai-router) | Route the message to a named branch the LLM chooses after inspecting it. |
| [`ai-mapping`](/reference/blocks/ai#ai-mapping) | Reshape the body to a target shape described by a prompt and optional schema. |
| [`ai-retry`](/reference/blocks/ai#ai-retry) | On failure, let the LLM revise the message and retry the chain. |
| [`clear-agent-memory`](/reference/blocks/ai#clear-agent-memory) | Erase an ai-agent conversation thread's stored memory. |
| [`mcp-router`](/reference/blocks/ai#mcp-router) | Turn a flow into a stateless MCP server behind an HTTP source. |
