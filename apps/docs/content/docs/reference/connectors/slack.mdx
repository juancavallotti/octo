The `slack` connector holds the bot credentials and talks to the Slack Web API; its blocks send and edit messages, add reactions, look up users, and verify and normalize inbound events. Inbound Slack events, slash commands and interactivity arrive one of two ways. Over the [http](/reference/connectors/http) connector, Slack posts them to a route you own and `slack-verify-request` authenticates them. In Socket Mode, the connector's own `slack` source holds a websocket open to Slack, so no public route or signature is involved. Either way `slack-event` normalizes Events API events.

## `slack` connector

The connector provides the `slack` source for [Socket Mode](#slack-source-socket-mode); over HTTP, inbound traffic arrives through an `http` source instead. The blocks that bind to it are `slack-send-message`, `slack-update-message`, `slack-add-reaction`, `slack-lookup-user` and `slack-verify-request`. `slack-event` is a pure transformer and references no connector.

### Settings

| Setting | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `botToken` | string | Yes | none | Bot User OAuth token (`xoxb-...`) used to call the Web API. |
| `signingSecret` | string | No | none | Verifies inbound Slack request signatures; required to receive events over HTTP. |
| `appToken` | string | No | none | App-level token (`xapp-...`) with the `connections:write` scope; required by the `slack` source (Socket Mode). |
| `timeout` | duration | No | `30s` | Bounds each Slack Web API call. |

An `apiBaseURL` setting also overrides the Web API base (default `https://slack.com/api`), mainly for tests; it is not exposed in the editor.

### Error handling

Slack signals application errors with an `ok: false` response carrying an `error` code. Every block that calls the Web API has a `failOnError` setting (default `true`): when true a Slack error [fails the flow](/concepts/error-handling), when false the message passes through unchanged.

## `slack` source (Socket Mode)

**Slack Socket Mode** receives events, slash commands and interactivity over a websocket the runtime opens to Slack, instead of Slack posting to a public route. Turn on Socket Mode in your Slack app, generate an app-level token with the `connections:write` scope, and set it as the connector's `appToken`. No Request URL, `signingSecret` or `slack-verify-request` is involved: the connection itself is authenticated by the token.

| Setting | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `ackTimeout` | duration | No | `2500ms` | How long to wait for the flow's result before acknowledging without a response payload. Slack's deadline is 3 seconds. |

```yaml
source:
  connector: slack
  type: slack
```

Each envelope Slack sends becomes one message. Its `body` is the same payload an HTTP flow holds after `slack-verify-request`, so the blocks after the source are the same either way:

| `vars.slackEnvelopeType` | `body` |
| --- | --- |
| `events_api` | The `event_callback` payload; `slack-event` normalizes it. |
| `slash_commands` | The command's fields: `body.command`, `body.text`, `body.user_id`, `body.channel_id`, `body.response_url`. |
| `interactive` | The interaction payload, e.g. `body.type`, `body.user.id`, `body.actions`. |

Slack requires every envelope to be acknowledged within 3 seconds:

- An envelope that accepts a response payload (slash commands and most interactivity) is acknowledged with the flow's final body, which Slack shows as the reply, as an HTTP flow's response body would be. If the flow has not finished within `ackTimeout`, fails, or drops the message, the acknowledgement carries no payload and the flow keeps running.
- Any other envelope, including every Events API event, is acknowledged as soon as it arrives, so a slow flow never makes Slack redeliver it.

The source reconnects when Slack asks it to or the connection drops. Each replica opens its own connection and Slack delivers every envelope to one of them, so scaling out needs no coordination. See `samples/slack-socket-mode.yaml`.

## `slack-verify-request` block

**Slack Verify Request** authenticates an inbound Slack request delivered over the `http` connector. It verifies the HMAC-SHA256 signature over the exact request bytes using the connector's `signingSecret`, rejects timestamps more than 5 minutes from now (bounding replay), and aborts the flow on a bad or stale signature.

| Setting | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `connector` | string | Yes | none | Name of the `slack` connector to use. Its `signingSecret` must be set. |
| `signatureHeader` | string | No | `X-Slack-Signature` | Variable holding Slack's request signature. |
| `timestampHeader` | string | No | `X-Slack-Request-Timestamp` | Variable holding Slack's request timestamp. |
| `rawBodyVar` | string | No | `rawBody` | Variable holding the exact request body; must match the http source's `rawBodyVar`. Optional when the http source uses raw-content mode (`rawBody: true`), where the block reads the raw body directly and re-parses it into `body`. |

The http source must expose the exact request bytes, either with `rawBodyVar: rawBody` or with `rawBody: true`, and copy the two signature headers into variables:

```yaml
source:
  type: http
  settings:
    path: /slack/events
    headers: [X-Slack-Signature, X-Slack-Request-Timestamp]
    rawBodyVar: rawBody
```

In raw-content mode the block parses the verified bytes into `body` according to the request's content type:

| Request | Content type | `body` after verification |
| --- | --- | --- |
| Events API | `application/json` | The JSON payload. |
| Slash command | `application/x-www-form-urlencoded` | The form fields as an object: `body.command`, `body.text`, `body.user_id`, `body.channel_id`, `body.response_url`, `body.trigger_id`. A repeated field becomes a list. |
| Interactivity (buttons, modals, shortcuts) | `application/x-www-form-urlencoded` with a single `payload` field | The JSON inside `payload`, e.g. `body.type`, `body.user.id`, `body.actions`. |

A body that fails to parse stays the raw `{contentType, rawData}` envelope. Slash commands and interactivity need `rawBody: true` on the http source: without it the source parses every body as JSON and rejects a form post.

```yaml
source:
  type: http
  settings:
    path: /slack/commands
    headers: [X-Slack-Signature, X-Slack-Request-Timestamp]
    rawBody: true
```

The flow's response body is Slack's immediate reply, so a slash command answers with `{"response_type": "ephemeral", "text": ...}` (only the caller sees it) or `in_channel`. Slack expects that reply within 3 seconds; slower work goes through [queue-dispatch](/reference/connectors/queue) to a worker that POSTs its result to `body.response_url`. `samples/slack-slash-command/` shows both, and the [Slack bot guide](/guides/slack-bot#reply-later-through-response_url) walks through it.

When the payload is Slack's one-time URL-verification handshake (`type: url_verification`), the block sets `vars.slackChallenge` to `true` so the flow can branch, echo `body.challenge` back, and skip event handling.

## `slack-event` block

**Slack Event** normalizes a verified Slack `event_callback` into a flat shape and filters it. Messages that are not an `event_callback`, whose event type is not in the allowlist, or that fail the filter predicate are dropped: the flow stops for them, and over HTTP that responds `204`.

| Setting | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `eventTypes` | string[] | No | allow all | Allowlist of event types (e.g. `app_mention`, `message`). |
| `filter` | expression | No | none | CEL predicate over the normalized body; drop the event when false. |

The block replaces `body` with:

| Field | Source |
| --- | --- |
| `body.type` | Inner event `type` (e.g. `app_mention`). |
| `body.user` | Event `user`. |
| `body.channel` | Event `channel`. |
| `body.text` | Event `text`. |
| `body.ts` | Event `ts`. |
| `body.threadTs` | Event `thread_ts`. |
| `body.botId` | Event `bot_id`, null for human messages; filter on `body.botId == null` to ignore the bot's own messages. |
| `body.teamId` | Envelope `team_id`. |
| `body.eventId` | Envelope `event_id`. |
| `body.raw` | The untouched inner event, for anything the flat fields omit. |

## `slack-send-message` block

**Slack Send Message** posts a message to a Slack channel or user through a `slack` connector (`chat.postMessage`). The target is a channel ID or a user ID; Slack opens a DM when given a user.

| Setting | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `connector` | string | Yes | none | Name of the `slack` connector to use. |
| `target` | expression | Yes | none | CEL expression for the channel ID or user ID (Slack DMs a user). |
| `text` | expression | Required unless `blocks` is set | none | CEL expression for the message text. |
| `threadTs` | expression | No | none | CEL expression for a parent message `ts`, to reply in-thread. |
| `blocks` | expression | No | none | CEL expression producing Block Kit blocks (a list). |
| `failOnError` | boolean | No | `true` | Turn a Slack API error into a flow error. |

On success the posted message's coordinates are folded into variables so a later block can react to or update it: `vars.slackChannel` is the channel it was posted to, and `vars.slackTs` its timestamp (`ts`).

## `slack-update-message` block

**Slack Update Message** edits a message the bot previously posted (`chat.update`), addressed by channel and timestamp.

| Setting | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `connector` | string | Yes | none | Name of the `slack` connector to use. |
| `channel` | expression | Yes | none | CEL expression for the message channel ID. |
| `timestamp` | expression | Yes | none | CEL expression for the target message `ts`. |
| `text` | expression | Required unless `blocks` is set | none | CEL expression for the new text. |
| `blocks` | expression | No | none | CEL expression producing replacement Block Kit blocks (a list). |
| `failOnError` | boolean | No | `true` | Turn a Slack API error into a flow error. |

A typical pattern posts a "working…" message with `slack-send-message`, then updates it via `vars.slackChannel` and `vars.slackTs`.

## `slack-add-reaction` block

**Slack Add Reaction** adds an emoji reaction to a message (`reactions.add`), typically to acknowledge an event.

| Setting | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `connector` | string | Yes | none | Name of the `slack` connector to use. |
| `channel` | expression | Yes | none | CEL expression for the message channel ID. |
| `timestamp` | expression | Yes | none | CEL expression for the target message `ts`. |
| `emoji` | expression | Yes | none | CEL expression for the reaction name without colons (e.g. `white_check_mark`). |
| `failOnError` | boolean | No | `true` | Turn a Slack API error into a flow error. |

## `slack-lookup-user` block

**Slack Lookup User** resolves a Slack user into a variable, by email (`users.lookupByEmail`, the default) or by Slack user ID (`users.info`), selected with `by`.

| Setting | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `connector` | string | Yes | none | Name of the `slack` connector to use. |
| `by` | enum: `email` \| `id` | No | `email` | How to resolve the user. |
| `email` | expression | With `by: email` | none | CEL expression for the email address to resolve. |
| `user` | expression | With `by: id` | none | CEL expression for the Slack user ID to resolve (e.g. `U123`). |
| `resultVar` | string | No | `slackUser` | Variable to store the user object in. |
| `failOnError` | boolean | No | `true` | Turn a Slack API error into a flow error. |

The stored value is Slack's full user object, e.g. `vars.slackUser.real_name`, `vars.slackUser.profile.email`.

## Example

Adapted from `samples/slack-bot.yaml`: verify events, answer the URL-verification handshake, and reply to @-mentions.

```yaml
service:
  name: slack-bot

env:
  - name: SLACK_BOT_TOKEN
    required: true
  - name: SLACK_SIGNING_SECRET
    required: true

connectors:
  - name: api
    type: http
  - name: slack
    type: slack
    settings:
      botToken: ${SLACK_BOT_TOKEN}
      signingSecret: ${SLACK_SIGNING_SECRET}

flows:
  - name: slack-events
    source:
      connector: api
      type: http
      settings:
        path: /slack/events
        # Copy Slack's signature headers into vars and the exact request bytes
        # into vars.rawBody, so the signature can be verified over the raw body.
        headers: [X-Slack-Signature, X-Slack-Request-Timestamp]
        rawBodyVar: rawBody
    process:
      # 1. Authenticate the request (aborts on a bad or stale signature) and
      #    flag Slack's URL-verification handshake.
      - type: slack-verify-request
        name: verify
        settings:
          connector: slack

      # 2. Either echo the URL-verification challenge, or handle the event.
      - type: if
        name: challenge-or-event
        condition: has(vars.slackChallenge)
        then:
          process:
            - type: set-payload
              settings:
                value: '{"challenge": body.challenge}'
        else:
          process:
            # Keep only @-mentions, ignoring the bot's own messages.
            - type: slack-event
              name: mentions
              settings:
                eventTypes: [app_mention]
                filter: body.botId == null
            # Resolve the mentioning user so the reply can greet them by name.
            - type: slack-lookup-user
              name: whois
              settings:
                connector: slack
                by: id
                user: body.user
            # Reply in the same channel.
            - type: slack-send-message
              name: reply
              settings:
                connector: slack
                target: body.channel
                text: '"thanks " + vars.slackUser.real_name + ", you said: " + body.text'
```

<Callout type="warn">
Slack expects a `2xx` within 3 seconds, so keep the event flow fast and offload slow work with [queue-dispatch](/reference/connectors/queue).
</Callout>
